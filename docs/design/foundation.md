# Foundation v0.1

## 設計原則

- [デザイン方針](../design.md)に従い、最初の簡易モックと既存UIを視覚的な基準とする。
- 色・文字・余白は用途に応じたトークンを使い、見た目の一貫性を保つ。既存の表現を尊重し、必要になった用途から整える。
- 日本語を含めシステムフォントを基本とし、新たなWebフォントやUIライブラリに依存しない。
- 原則としてアニメーションや視差効果を使用しない。操作に対するフィードバックは、動きを伴わない視覚的な状態変化で表現する。
- WCAG 2.2 AAを目標とする。自動テストだけで準拠済みとは判断しない。

## トークンの使い方

実装値は [tokens.css](../../src/styles/tokens.css)、共通の振る舞いは [global.css](../../src/styles/global.css) を参照する。値やCSSの詳細はこの文書に重複して記載しない。

通常のCSSから `color: var(--color-text)` のように参照する。背景・文字・装飾線・操作部品の境界を用途で区別し、同じ色でも役割を混同しない。

- `--color-border` は装飾用。操作部品や選択状態の唯一の手掛かりにしない。
- `--color-border-control` は意味のあるUI境界用。実際の隣接色や状態ごとにコントラストを確認する。
- `--color-focus` はフォーカス用。背景に応じて視認性を確認し、表示をクリップ・遮蔽しない。

## アクセシビリティの原則

- 通常文字は4.5:1以上、大きな文字は3:1以上、意味のある非テキストUIは原則3:1以上のコントラストを確保する。背景・透明度・操作状態を含む実際の組合せで判断する。
- セマンティックHTMLを基本にし、操作対象には適切な名前、画像には用途に応じた代替テキストを付ける。
- キーボードで操作でき、フォーカス位置が見えるようにする。文字拡大・ズーム・狭い画面でも内容と操作を保つ。
- 将来、動きが必要な機能を実装する場合は、その時点でアクセシビリティへの対応を個別に検討する。
- スクリーンリーダー、強制カラー、実機などでも確認する。個別の検証結果や未検証事項はPRに記録する。
